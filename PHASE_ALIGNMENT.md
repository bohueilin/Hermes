## 1. Phase 8 — what was delivered

34 commits, 73 files, +12,327 / −154.

**Foundations.** Scenario schema 4.0 (first version permitting a scripted challenge and a fault
profile together, plus `tags`/`odd`/`adas`/`requirements` and a moving ego spawn); trace-layer
version gates; a fixture-regeneration path; an import-provenance guard.

**ADAS.** FCW + AEB as an ordinary `DrivingPolicy`. AEB stages on **required deceleration**
(`a_req = closing² / (2·usable_gap)`) rather than TTC, because a braking lead makes TTC optimistic
exactly when it matters. Four findings — two hard (`threat_response`, `no_false_intervention`),
two soft (`brake_onset_margin`, `warning_timing`) — computed by an offline oracle whose thresholds
live in a different config from the controller's.

**Evaluation acceptance.** `config/phase8-seeded-defects.yaml`: three controllers broken one way
each, run as five cases, each naming the finding that must catch it. The test parametrises from
the YAML at collection time so spec and test cannot drift. A baseline control prevents "the gate
caught it" collapsing into "the gate always fails".

**Agentic layer.** Eight tools across READ/EXECUTE/MUTATE, dry-run by default on both non-READ
tools; a budget ledger; citations that re-resolve against the bundle; agent proposals recorded
*beside* the deterministic classification. `promote_regression` refuses without an approval bound
to the SHA-256 of a draft's exact bytes.

**Regression flywheel.** failed run → triage → draft → validate → approve → promote → rerun.
Drafts derive from the trace geometry at the failing event; a requirement floor blocks a draft
that would subtract coverage; the derived case must discriminate.

**Five scenarios** (`aeb_lead_hard_brake`, two nominal, `cut_in_near`, `cut_in_far`), of which
three match named P0 catalog entries out of 22 + 4 nominal.

**Defects found and fixed:** a release-gate fail-open (a hard finding without its own precedence
branch reported PASS *while failing*); scenario identity using a forked serializer; a suite that
could not run on a fresh clone; two float32 boundary defects.

## 3. Coordination rules

Phase 8 is the fragile side, for a specific reason: **63 evidence bundles sit under `artifacts/`,
which is gitignored, and only 13 are registered in `config/phase8-fixture-registry.yaml`.** The
other 50 cannot be regenerated by any committed path. Nearly every rule below exists because the
failure mode is *a wrong number that verifies cleanly*, not a red test.

### Protecting Phase 8

**1. [SILENT] Do not add, remove or rename any field on `ScenarioDefinition` or anything reachable
from it** (`domain/models.py:347-370`). Adding the field to `_SCHEMA_4_ONLY_FIELDS` does **not**
make it safe — that list only strips for `schema_version != "4.0"` (`scenarios/loader.py:53`), so
every schema-4.0 ADAS bundle flips to `INVALID_EVIDENCE` while `pytest` stays green. Phase 9
scenario data belongs in a new model under a new namespace, keyed by name.

*Verified and reassuring:* widening `adapter: Literal["fake","metadrive"]` to add a member is
**digest-neutral** — `model_dump()` emits the value, never the type. It is whatever *ships
alongside* the Literal that breaks things.

**2. [SILENT] Do not run `hermes fixtures regenerate --force`, re-run `make demo-*` to green a
test, or delete `artifacts/`.** Regeneration restores only the 13 registered fixtures and
permanently destroys the other 50 — including the `flywheel-*`, `cutin-*` and `d-near/d-far-*`
runs the evaluation-adequacy argument depends on. Revert the change instead.

**3. [SILENT] Do not change `ControlConfig.max_braking_mps2` (6.0) to the measured value.** This
is the counterintuitive one and the most likely mistake. Both oracle thresholds are *fractions of
that constant* — `threat_authority_fraction * authority` (`verifiers/adas.py:142`) and
`onset_authority_fraction * authority` (`:263`). Raising 6.0 toward the measured ~11 m/s² **raises
both thresholds**, so fewer steps are labelled threats and later braking passes. It weakens the
oracle rather than the controller, and seeded defects go uncaught with the suite still green.

**4. [SILENT] Leave the `dynamics_limitation` strings in `gates/release.py:225-229` byte-identical,
and pass `adapter_name=` explicitly.** MetaDrive is the *unnamed* `else` arm, so the obvious
dict-lookup refactor silently reassigns it; the `fake` default stamps a false provenance
disclaimer into `verdict.json` with nothing red.

**5. [SILENT] Do not `.get()`-refactor the adapter chains in `evidence/verification.py`
(750/772/943, 1296-1321), and do not import a simulator package from `evidence/`, `gates/` or
`verifiers/`.** The `else` at `:943` is the only thing that fails an unknown adapter closed. The
boundary test blocks only the literal names `hermes.adapters` and `metadrive`, so `import mujoco`
there passes green while voiding independent re-verification. Add any new engine name to that
list in the same commit.

### Protecting Phase 9

**6. Work in a separate git worktree.** `feat/phase8-adas-lab` is on the `github` remote as of
2026-08-22 (pushed by the sandbox session; fast-forward pushes only). `orchestrator.py:170` stamps
`repository_dirty` from
`git status --porcelain`, so an uncommitted file in this checkout taints every bundle anyone
generates, and a differing `repository_commit` makes any baseline/candidate pair `NOT_COMPARABLE`.

**7. Always run with `PYTHONPATH=<repo>/src`.** The `hermes-dev` editable install resolves `hermes`
to the **Phase 7 codex worktree** — activating the env without the prefix silently measures a
different tree and reports a meaningless green suite. `make preflight` guards this.

**8. Baseline `artifacts/` before and after any change under
`src/hermes/{domain,evidence,gates,scenarios,runtime,adapters}`.** A green `pytest` is not
evidence: `artifacts/` is gitignored, and the ADAS tests build and verify a bundle in the same
process, so they cannot detect an identity shift.

```bash
for d in artifacts/*/; do printf '%s ' "$d"; hermes verify-artifact "$d" | grep -E 'Artifact integrity|Verdict'; done
```

## 4. The one place the two efforts genuinely help each other

**The MetaDrive brake-authority measurement — transferring one direction, as data, not as a code
change.**

`sandbox/mujoco/metadrive_brake_probe.py` is the only instrument either effort has that *measures*
physical braking authority instead of assuming it. Its headline — "~11 m/s² peak" — **understates
its own data.** The probe's `max()` runs over consecutive samples *within* the post-brake trace, so it
excludes the first brake step, which is the largest drop in both curves:

| entry speed | reported peak | first-step drop (excluded) | true peak | reported mean | mean, correct intervals |
|---|---|---|---|---|---|
| 8.29 m/s | 11.24 | 8.29 → 7.02 = **12.70** | 12.70 m/s² | 8.54 | 9.76 m/s² |
| 13.81 m/s | 11.24 | 13.81 → 12.55 = **12.60** | 12.60 m/s² | 9.61 | 11.07 m/s² |
| 17.12 m/s | — | episode ended after one brake step | — | — | — |

(The mean divides a `len(vs)−1`-interval drop by `len(vs)` intervals.) So the steady-state
deceleration is ~11 m/s² and the true peak is ~12.6–12.7 m/s² — which agrees with Phase 8's
in-pipeline ~13 m/s² far more closely than the handoff states. Derived here from the probe's own
`speed_trace`; the probe script belongs to the sandbox session and has not been edited.

The 17.12 m/s run has no curve because the probe uses MetaDrive's *default* map and runs out of road
at speed. Every committed ADAS scenario runs at 20 m/s on `map='S'` with a 240 m destination.

Phase 8's single largest known weakness is that `max_braking_mps2 = 6.0` is an unmeasured guess
that the oracle treats as physical ground truth, while the code prose calls the onset criterion
"physically grounded". Phase 9 needs a real decel-vs-speed curve anyway for its MetaDrive→FleetLab
calibration bridge. Same measurement, both needs.

What should transfer: a probe producing usable points **at 20 m/s** on the **scenario-faithful
config** (`map='S'`, `traffic_density=0`, a destination long enough to brake from 20 m/s) — the
current probe has two points below 14 m/s and a null at 17.12 m/s.

Also informational: the sandbox's `pilot_adapter.py` implements the `SimulatorAdapter` shape
against a MuJoCo AEB scene and conforms — all 9 protocol members, exact field parity on all 5 data
models, AST-checked against the real `contracts.py`/`models.py`. Its one surfaced integration gap is
the `adapter` Literal (§5), which is digest-neutral to widen. That unblocks Phase 9's bridge and gives Phase 8 what it needs to either re-derive the
authority *fractions* alongside the authority (so the oracle keeps discriminating) or honestly
relabel the criterion as simulator-relative.

What must **not** transfer: the number itself as a default edit. See rule 3.

## 5. The one thing most likely to be wastefully duplicated

**The adapter seam.** Both efforts will independently discover and half-fix the same
`fake`/`metadrive` binary branches, scattered across at least eight files — `verification.py`
(750/772/943/958/1298/1308), `gates/release.py:225`, `cli.py` (334/371/392/414),
`fixtures/registry.py` (63/95/259), `agents/tools.py` (312/363/392), `orchestrator.py`
(517/531/552/561), `trace.py:831`, `domain/models.py` (355/407/414/422/473).

Each looks like a trivial local fix in isolation. Two uncoordinated passes produce conflicting
partial widenings — and the specific hazard is that widening `cli.py:334` without `cli.py:392`
turns a clean `CONFIGURATION_ERROR` into a **silent MetaDrive run labelled as something else**.

Several of these branches are `if fake / elif metadrive` with **no `else`** (`verification.py:1298`
and `:1308`), so a third adapter's simulator provenance would never be validated at all.

**Assign the whole seam to one owner, in one commit.** Do not let both efforts touch it.
