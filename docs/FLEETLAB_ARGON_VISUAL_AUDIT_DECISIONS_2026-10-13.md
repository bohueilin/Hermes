# FleetLab — Argon visual audit decisions

Date: October 13, 2026 (America/Los_Angeles).

## Review method and recommendation

Argon explicitly reported access to the static HTML shell, without access to the rendered SPA states or City Explorer. Its report is useful design ideation, not an observed usability, accessibility, performance or map audit. The implementation was selected against the actual rendered site, existing models, automated tests and source-bound release budgets.

**Recommendation:** preserve the welcoming cream/sage identity and original 3D concept film; improve the route into learning and provide small, readable diagrams that explain the actual models. Use restrained dark green visual stages inside the existing light interface. Keep real simulation controls and results prominent.

## Finding-by-finding decisions

|---|---|---|
| Show narrative intuition before analytical detail | Adopt | Three illustrated Home learning paths connect shared resources, rider service and model limits to explicit next actions. |
| Collapsible concept drawers | Adopt | Native, initially collapsed disclosures explain depot readiness, the fleet cycle, street queues and paired comparisons. They do not run models. The Depot Compare action remains ahead of the disclosure. |

| Dark obsidian/neon rebrand across all pages | Decline | A broad rebrand conflicts with the established welcoming light theme and is not justified by a shell-only review. Dark surfaces are limited to teaching visuals. |
| Generate a new looping cinematic hero | Retain existing asset | FleetLab already has an original 3D film, accessible controls and restricted-motion paths. Reframed it without a new asset, playback system or claim of recorded simulation. |
| RSL/cost/trust trilemma pictures | Reframe | Home cards teach capacity, service and model limits. Trust is not a synthetic quantity that can be traded away or represented as a green quality score. |
| Four time-of-day dioramas synchronized to Fleet day | Defer | A static conceptual cycle is appropriate now. A timed illustration would need an explicit, tested binding to actual accepted simulation state; invented daylight stages are not records. |
| Street sensor occlusion / intersection yielding pictures | Decline for this model | The street model teaches queues in a simplified directed network; it does not establish perception or physical driving behavior. Added a queue primer and a plain-language PUDO definition. |
| A/B video with queues on the left and zero queues on the optimized right | Decline / replace | Paired primer gives A and B the same visual treatment and asks the visitor to inspect both improvements and regressions. No winner is predetermined. |
| Common random numbers eliminate variance | Correct | Matching workload and travel-variation seeds can reduce noise in a difference. It does not eliminate uncertainty or guarantee improvement. |
| Five serial depot zones: arrival → cleaning → charge → calibration → ready | Correct to implemented lesson | The first Depot flow lesson permits charging and upload to overlap; its local step follows upload. Energy AND data prerequisites determine readiness. No universal physical depot layout is implied. |
| Eight-bay looping charger animation | Defer | A fixed decorative stall count could be mistaken for configured capacity. The current diagram explains the dependency without invented capacity. |
| Generated SF topography and three/four depot hubs | Decline | Invented terrain, siting and depot counts must not appear to qualify a sourced map or explain recorded results. All City release files and source offers remain byte-identical. |
| Emerald = charging / high trust; cyan = optimal flow | Decline | Colors cannot grant authenticity, safety or deployment authority. Diagram accents distinguish explicitly labeled energy/data paths only. |
| Scroll-driven scrubbing, parallax, glass overlays | Defer | These effects add input, motion and rendering complexity without improving the bounded teaching questions in this wave. No scroll interception, parallax or extra animation was added. |
| Brand independence | Retain | Existing non-affiliation and simulation boundaries remain. No operator logos, copied vehicle designs or implied operator endorsement were added. |
| New AVIF/WebP/Veo media pipeline | Not needed in this wave | Used native HTML/CSS/SVG and the existing film. No new media dependency, network request or external service was introduced. |
| Lighthouse >92, FCP <1.2 s, first experiment <20 s, comprehension <60 s | Treat as proposed targets | These are not observed results. Byte-budget and responsive checks passed; a dated performance run and uncoached visitor study are needed before reporting those targets as achieved. |

## Validation scope

The implementation handoff records actual tests, release identities, readbacks and package sizes. Browser checks covered the desktop layout and 320/390/768 px widths, disclosure interaction, route discovery and an executed Depot comparison. This is not a completed physical-phone, native screen-reader, operating-system preference or human comprehension review.

The conceptual diagrams do not import records, model execution or clock logic. Every diagram is labeled **Concept diagram · not simulation output**. NF04 and Delivery order records and verifier behavior are unchanged. Existing SF qualification remains **HOLD / BLOCKED_MAP_QUALIFICATION**, authenticity **NOT_AUTHENTICATED**, operational deployment permission **NONE**.

## Top risks + mitigations

- **Visitors mistake illustrations for evidence:** visible concept captions, scoped first-lesson wording, neutral policy arms, no generated SF geography.
- **Added explanation obscures action:** diagrams start collapsed; existing primary actions and phone reading order remain intact.
- **Future assets exceed release budgets:** no new bitmap/video payload; hard package gates retained. The current release has little remaining offline/metadata headroom, so a future asset/lesson wave must address packaging before adding payload.

## Next 3 actions

1. Use the published Home → first Depot lesson path in the next visitor review; ask the visitor to explain why a charged vehicle can still wait.
2. Complete the already-open physical-device, native accessibility and independent comprehension observations without treating narrow-width checks as substitutes.
3. Use observed misunderstanding and measured payload headroom to scope the next visual or Network Flows enhancement. SF map qualification stays a separate prerequisite.
