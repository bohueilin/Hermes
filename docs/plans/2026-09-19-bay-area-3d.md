# Bay Area 3D fleet simulation implementation plan

> Use superpowers:subagent-driven-development for bounded tasks and independent review. One implementation subagent at a time; root handles disjoint rendering/UI work. Keep all work local and uncommitted.

**Goal:** A true 3D operational simulation on real Bay Area geography, all requested places selectable, with editable Jaguar I-PACE / Ojai fleet profiles affecting energy, time and depot work.

**Architecture:** Check in a compact, attributed OpenStreetMap extract and routing facade. Extend the operational teaching model with optional real-road geography and per-vehicle profiles while preserving the existing synthetic and regional baselines. Render recorded car paths and depot states with native WebGL geometry and an orbitable camera; retain an accessible flat/table fallback. Provider data is map geometry, not real traffic or commercial service coverage.

**Stack:** Native browser JavaScript, WebGL, DOM, existing offline packer; Node built-in tests. No CDN, runtime data download or account required. Keep the offline package under its current 2 MB cap where practical using compact regional data.

## Decisions

- Native WebGL gives real 3D without a large renderer dependency or GPU simulator installation. This is operational animation, not photorealistic driving simulation.
- Real roads are sourced from OSM and frozen locally; congestion/weather/demand remain synthetic and editable.
- Ojai uses a conspicuous illustrative profile because public operational specifications have not been verified. Profile sensitivity is useful without claiming real fleet performance.
